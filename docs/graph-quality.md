# 图谱数据质量：实测的噪声形态与处理规则

这份文档记录**怎么发现**图谱里的噪声、每条规则**为什么这么判**，以及**已知治不了的部分**。
不是设计文档 —— 设计在 `docs/2026-09-16-ai-analysis-new-conversation-design.md`，
这里只有量出来的数据和据此定下的规则。

起因：拿插件自己生成的 `session-<id>.json` 逐项核对时发现，抽取**本身是忠实的**
（轮次 / 助手正文 / 用户消息 / 工具调用 / 决策 五类对象的条数与源日志逐条对齐，
0 缺失、0 多余），但**实体层的信噪比是反的** —— 噪声度数更高、排得更前。

---

## 一、量出来的噪声形态

样本：本插件作者的一次真实会话，28 轮 / 997 段 / 325 个实体，
用 `zh_core_web_sm` + `en_core_web_sm` 抽出。

| etype | 个数 | 实测内容 | 判定 |
| --- | --- | --- | --- |
| PERSON | 125 | `graph`(度 23)、`tool`、`out`、`locale`、`TypeError`、`text`、`title`、`白名单`、`简单力` | 几乎全错 |
| ORG | 48 | `CSS`、`SKOS`、`AI`、`ISO`、`静默复查`、`中英`、`中心度` | 多数错 |
| CARDINAL | 28 | `134px`、`625px`、`上百`、`②本体` | 全错 |
| DATE | 18 | `今天`、`localhost`、`汉化`、`00014 个月` | 全错 |
| PRODUCT | 22 | `GUI`(对)、`browserAllowedLoopback`、`320px`、`≤320px` | 半对 |
| GPE | 19 | `白捡`、`扇出`、`上界`、`平台层`、`硬伤`、`里加` | 几乎全错 |
| TIME / MONEY / QUANTITY / PERCENT | 27 | `6个月`、`十几行` | 全错 |
| FAC / NORP / LOC | 13 | `假数据`、`平方级`、`zhcorewebsm` | 几乎全错 |
| WORK_OF_ART / LAW / EVENT | 9 | `GROUP BY`、`Exclude all local artifacts` | 全错 |

两类**专门的**问题：

1. **被切碎的词**。`cy` 是全图度数第五的「实体」（度 44），来源是
   `cytoscape/d3/mermaid` —— 模型把第一个词切了一半。同类还有
   `MIT LICENSE` → `MIT LICEN`。这类东西会带上很高的度数，因为每次提到
   那个完整词都会给这半截加一条边。
2. **自指闭环**。这场对话本身在讨论图谱噪声，于是 `numpy`、`cy`、`graph`
   这些名字被写进了助手可见回复 —— 它们因此**真的**成了对话里的词。
   数据里最荒诞的一幕：同一个概念既是噪声的来源，又是讨论对象。
   这解释了为什么 `cy` 修完之后仍然在（见下面「已知局限」）。

## 二、四条规则

规则全部落在 `src/graph_worker.py` 的实体层，判定边界由
`scripts/check-entity-rules.mjs` 钉住（每条规则都有正例**和反例** ——
拦噪声时最容易顺手拦过头）。

### 1. 碎片：跨度的紧邻字符还是字母/数字

```
cy      ⊂ cytoscape/d3/mermaid    → 后面是 t，拦
MIT LICEN ⊂ MIT LICENSE           → 后面是 S，拦
d3      ⊂ cytoscape/d3/mermaid    → 前后是 /，留
```

**只对含 ASCII 字母的名字判**。中文没有词间空格，紧邻汉字是常态
（`白名单里` 的「里」就紧挨着），按邻接判会把正常词整片丢掉。

### 2. 序数词按整词判，不按类型

`^第[一二三四五六七八九十百千两0-9]+$` 加上少数英文序数词。

**关键反例**：zh 模型把名词 `第三方` 也标成了 ORDINAL ——
按类型丢会误伤它。所以判据只能落在词本身。

### 3. 类型纠错：证据累积，不按当次提及

写在反引号里的、或长成标识符的（小写开头的驼峰 / 下划线 / `::` / `->`），
一律是无歧义的代码标识符 → 类型改成 `CODE`。

**两个踩过的坑**：

- *当场改类型是错的*。节点的 `etype` 在**第一次**提及建立节点时就定下来了，
  后面就算带证据也覆盖不了 —— 结果取决于哪一段先被扫到。实测 `numpy` 就是受害者：
  它有时裸写（「因 numpy ABI 冲突损坏」）、有时带反引号（「`` `numpy` `` 原版本 1.26.4」），
  于是它一直挂着模型给的 GPE。改成先收证据、最后统一改。
- *形状判据必须收窄到「小写开头的驼峰」*。`(?<=[a-z])[A-Z]` 对
  `GitHub` / `TypeScript` / `PostgreSQL` 同样成立，而这些是专有名词不是标识符。
  `browserAllowedLoopback` ✓、`openDetails` ✓、`std::vector` ✓；
  `TypeScript` ✗、`GUI` ✗（`GUI` 还合法地是 PRODUCT，一刀切 PRODUCT 会误伤它）。

### 4. 含中文的标签：spaCy 的类型实测等于随机

中文标签上的 PERSON / ORG / GPE / FAC / NORP / LOC / PRODUCT 实测没有区分度
（见第一节的表），所以**改成诚实的 `UNKNOWN`**。

这里刻意**只改类型、不丢节点**：`扇出`、`上界`、`白名单` 都是这场对话真正在谈的概念，
它们不该因为模型标错类型就被删掉。`LANGUAGE` 标得准（`中文` / `英文`）予以保留；
带反引号或标识符形状的一律还是 `CODE`。

反过来，度量/时间类（CARDINAL / DATE / TIME / MONEY / QUANTITY / PERCENT）
以及 WORK_OF_ART / LAW / EVENT 是**整条丢掉** —— 实测这些类型里没有信息量，
真正的日期如 `2026-09-16` 早被既有的纯数字规则拦住了。

## 三、另外两处修复

### 工具节点补上详情正文

`content` 一路回落到 `label`（只有一行描述），于是点开一个 bash 节点
看不到跑了什么命令、更看不到输出。而 `argsSummary` / `resultSummary`
在 JS 侧**算好了、也传过来了**，只是没人用。

现在 `content` = 标题 + 参数（≤300 字）+ 输出（≤200 字）。
Explorer 的搜索索引是拿 `content` 建的，所以补上之后命令与输出都可搜。
代价是图文件涨约 1MB（2210 个工具节点）。

### 实体的 valid_until 覆盖到全部

原来只在 `last_ms > first_ms` 时才写，理由是「只提过一次的实体是瞬时点，
给了会出现零长度区间」—— Explorer 的时间轴按 `[from, until]` 判活跃，
零长度等于任何时刻都不活跃，这个顾虑成立于前半段。

但「干脆不写」的代价是那些实体从被提到的那一刻起**永远活跃**：
时间轴拖到最后，开头一次性的提及仍然算「正在谈」。实测 325 个实体里
只有 100 个有 `valid_until`，另外 225 个一直全亮。

现在右端点取「最后一次提及**所在那一轮的结束**」（末轮用全会话最晚时刻兜底）：
区间有长度，且只在自己那一轮里活跃。

## 五、已知局限

诚实地列在这里，避免以后重复排查：

1. **中文碎片拦不住**。`张图`（来自「一张图」）这类切碎的中文词没有可用的邻接信号，
   仍在榜上（度 22）。要真正解决得靠分词后回对齐，目前没做。
2. **自指闭环治不了**。`cy` 修复后仍存活，因为助手在可见回复里**真的写了**
   `` `cy` `` 来讨论这个噪声（数据里有一条消息原话：「`cy` 现在来自**我自己在可见回复里讨论 `cy`**」）。
   界限完整、带反引号 —— 按任何合理判据它都是对话里的一个正当词条。
   只要会话在讨论图谱噪声，这个环就存在。
3. **模型本身的上限**。zh 模型对中文的类型判定基本不可用（第一节整张表），
   我们只能把类型改成 UNKNOWN 而不是修对 —— 真实类型信息在抽取这一步就丢了。
4. **停用词表是经验值**。`_STOPWORDS` 里的词是量出来的，不保证覆盖新会话里的新噪声。

## 六、怎么复现

```bash
# 量某个会话的图谱分布（⚠️ 输出务必给临时路径，别覆盖 DSH 正在用的图）
node scripts/rebuild-graph.mjs <sessionId> /tmp/graph-check.json

# 校验实体噪声规则的判定边界（不需要 spaCy，系统 python3 即可）
node scripts/check-entity-rules.mjs
```

改规则时 **必须两个都跑**：前者看真实分布有没有变好，后者看反例有没有被误伤。
